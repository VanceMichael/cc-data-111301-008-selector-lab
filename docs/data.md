# 来源资料约定

`annotations.json` 保存人工对页面的圈选。`record` 是记录区域 XPath；
`positive` 与 `negative` 均相对该区域，前者代表选中的字段节点，后者代表
明确排除、任何规则都不允许命中的邻近节点。`template` 是运营提供的模板类别，
同一模板可以有列表、详情等多类页面。`cards`、`detail` 与 `changed` 为不同
页面，`changed` 没有人工标签，专门用于演示对未参与生成页面的验证。
HTML 中的价格均是虚构数值。

## 规则生成只接受的三类定位信息

候选不记录绝对 XPath，也不按页面摘要猜答案，每条候选只表达：

- 记录内相对位置：用 nth-child 语义的显式层级（如 `./*[3][name()='strong']`），
  插入节点后位置变化会被直接暴露，而不是静默错位；
- 稳定属性：剔除 `id`、`class`、`style` 等易变属性后保留的数据属性；
- 文本锚点：目标自身或前置邻近元素的短文本；源自负例节点的锚点直接丢弃。

## 未决而不是猜一个节点

出现以下情况时结果带显式未决状态，绝不默认取第一个节点：

- 候选在某页面无命中（`no_hit`）或多重命中（`multi_hit`）；
- 命中了 `negative` 声明的节点（`negative_hit`），例如把划线原价当售价；
- 同一字段的多个候选命中了不同节点（`candidate_disagreement`）；
- 模板定位器在多个模板上同时命中（`template_ambiguous`）或都不命中；
- 记录结构签名与生成样本不一致（`structure_drift`），说明布局发生了扰动。

## 生成与执行的边界

`generate` 只写 `drafts/`，草稿按内容寻址、天然幂等；`publish` 把运营显式
选定的候选固化为不可变规则包写入 `packs/`；`activate` 用指针固定运行版本。
新增标签只会产生新草稿，不会改动任何已发布的规则包；规则包被篡改时摘要
校验失败、拒绝执行。运行期只读取激活的规则包，同一版对同一页面重复执行
得到完全相同的定位结果。

本项目只处理已经保存在本地的页面样本，不发起任何网络请求。
